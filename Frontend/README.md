# СанАрт — Frontend (мокап)

Чистая вёрстка без бэкенда: HTML/CSS/JS, без сборщика и фреймворка — открывается сразу в браузере
(лучше через локальный сервер, см. ниже, чтобы избежать ограничений `file://` на относительные пути).

Готова **страница «Дашборд»** (`index.html`). Остальные 4 вкладки (Аудитория, Мероприятия, Отзывы,
Отчёты) в сайдбаре размечены как «скоро» — заглушки, не ссылки в никуда.

## Как открыть

Через любой статический сервер, например:

```bash
cd Frontend
python -m http.server 8080
```

и открыть `http://localhost:8080/index.html`. Открытие файла напрямую двойным кликом тоже работает
в большинстве браузеров (относительные пути `assets/...` резолвятся нормально), но локальный сервер —
надёжнее.

## Структура

```
Frontend/
  index.html                     — страница «Дашборд»
  assets/
    css/
      tokens.css                 — ЕДИНЫЙ источник цветов/шрифтов/отступов/радиусов (CSS custom properties)
      base.css                   — reset + базовая типографика, .pixel-heading, .corner-label
      layout.css                 — каркас: сайдбар / топбар / контентная сетка
      components.css             — карточки, KPI-карточки, табы периода, донат, ранжированные списки,
                                    bar-chart, geo-list, promo-banner, dq-banner
      pages/
        dashboard.css            — точечные правки только для страницы дашборда
    js/
      mock-data.js                — SANART_DATA: единственный источник мок-данных страницы
      icons.js                    — SANART_ICONS: набор inline SVG-иконок
      components/
        sidebar.js                 — renderSidebar(activeId) — рендер бокового меню
        topbar.js                   — renderTopbar() — рендер хедера (учреждение/период/пользователь)
        charts.js                    — renderAreaChart / renderDonutChart / renderRankList /
                                        renderBarChart / renderGeoList — переиспользуемые графики
      app.js                        — точка сборки страницы, переключение периода, KPI-карточки
```

## Как это устроено (важно перед подключением бэкенда)

- **Все данные** страницы лежат в одном объекте `SANART_DATA` (`assets/js/mock-data.js`). Ключи полей
  специально повторяют реальные таблицы проекта (`institutions_official`, `events_synthetic`,
  `attendance_synthetic`, `audience_synthetic`, `feedback_synthetic`) — чтобы заменить мок на ответ
  реального API можно было, просто подставив тот же объект, без переписывания компонентов.
- **Цвета/шрифты/отступы** — только через переменные в `tokens.css`. Если нужно поменять акцентный
  цвет или радиус скругления — правится одно место, а не разметка по всему проекту.
- **Компоненты — функции, а не HTML-партиалы**: `renderSidebar()`, `renderTopbar()`, `renderAreaChart()`
  и т.д. принимают данные и монтируются в контейнер по id. При добавлении следующих страниц
  (`audience.html`, `events.html`, `feedback.html`, `reports.html`) сайдбар/хедер/карточки переиспользуются
  один в один — меняется только `renderSidebar("audience")` и контент внутри `.content`.
- **Переключатель периода** (Сегодня/Вчера/Неделя/Месяц/Квартал) уже переключает набор KPI
  (`SANART_DATA.kpiByPeriod`) — заглушка того, как в реальности это будет дергать API с параметром периода.
- **Баннер контроля качества данных** (`#dq-banner`) — обязательное требование ТЗ (п. 08): если у части
  учреждений есть расхождения в `data_quality`, это должно быть видно, а не скрыто. Сейчас захардкожено
  «3 из 19», значение читается из `SANART_DATA.dataQuality`.
